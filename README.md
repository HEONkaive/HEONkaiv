## GitHub Pages에 업데이트하기

1. ZIP 파일을 압축 해제합니다.
2. `heon-archive` 폴더 안의 `index.html`, `app.js`, `styles.css`, `data/`, `assets/`, `tools/` 등의 **모든 파일과 폴더**를 기존 GitHub 저장소 **최상위(root)** 에 복사합니다. `index.html`이 루트에 있어야 합니다.
3. GitHub Desktop을 사용하면 이미지를 포함한 많은 파일을 한 번에 올리기 쉽습니다. **Commit to main → Push origin**으로 업로드합니다.
4. 처음 GitHub Pages를 설정한다면 **Settings → Pages → Deploy from a branch → main / (root) → Save**를 선택합니다. 기존 저장소라면 Pages 설정을 유지합니다.
5. 배포 후 이전 화면이 계속 보이면 `Ctrl + Shift + R`로 새로고침합니다.

### 기존 학습 기록

- 기록은 브라우저의 `localStorage` 키 **`heon.archive.learning.v1`**에 자동 저장됩니다.
- 동일한 사이트 주소·브라우저를 사용하면 기존 박무림·이서울·김혜원 교수님의 문제 ID와 제출 답안, 북마크, 학습 위치를 유지하도록 설계되어 있습니다.
- 이서울 교수님 13문항에 기존 브라우저에서 별도로 지정한 정답이 있다면 **최초 한 번만 그 13문항의 오래된 정답 지정값을 초기화**하여 새 사용자 확정 기준으로 채점합니다. **제출 답안과 북마크, 다른 교수님 기록은 초기화하지 않습니다.**
- 다른 기기 간 기록 동기화는 없고, 브라우저 저장 정보를 삭제하면 학습 기록도 사라질 수 있습니다.

## 수정 및 교수님 추가 방법

```text
heon-archive/
├── index.html, app.js, styles.css
├── data/
│   ├── catalog.json, catalog.js
│   └── professors/
│       ├── park-murim.json, park-murim.js
│       ├── lee-seoul.json, lee-seoul.js
│       ├── kim-hyewon.json, kim-hyewon.js
│       └── choi-duyoung.json, choi-duyoung.js
├── assets/
│   ├── questions/           # 기출 원본 캡처
│   ├── figures/             # 문제에 직접 표시할 필수 그림
│   └── evidence/            # 강의안 검증 근거 / 미채택 검토 이미지
├── tools/
│   ├── sync_offline_data.py
│   └── check_v8_data.py
├── AUDIT_최두영_v8.md
├── AUDIT_이서울_v8_사용자정답.md
└── README.md
```

- **문제 문구 수정:** `data/professors/<교수님ID>.json`에서 `prompt`(지문) 또는 `choices`(선택지)를 수정합니다. **`id`는 변경하지 마세요.** `id`가 바뀌면 기존 학습 기록이 다른 문제와 연결될 수 있습니다.
- **`.js` 재생성:** JSON을 수정한 뒤 `python tools/sync_offline_data.py`를 실행하세요. `.js`는 오프라인 실행용으로 자동 생성되는 사본입니다. GitHub에는 JSON과 JS를 **함께** 반영합니다.
- **새 교수님 등록:** 교수님별 JSON과 이미지 폴더를 추가하고 `data/catalog.json`에 교수님을 등록한 뒤 같은 스크립트를 실행합니다.
- **정답 수정:** 직접 지정한 정답은 `answerSource:"user_confirmed"`, `validation.stage:"user_confirmed"`로 표시해 강의안 검증 정답과 반드시 구분하세요.

## 실행·검사

- 인터넷 연결 없이 로컬에서 실행할 경우 압축을 푼 `index.html`을 열어 볼 수 있도록 JS 데이터 사본이 제공됩니다. 브라우저의 `file://` 처리 정책은 환경별로 차이가 있으므로 문제가 보이지 않으면 GitHub Pages로 배포해서 확인하세요.
- 프로젝트 폴더에서 `python tools/check_v8_data.py`를 실행하면 4명의 문제 수, ID 중복, 정답 변경, 파일 경로, 그림 파일 누락을 검사합니다.
- 추가 테스트는 Chromium 브라우저에서 교수님 선택/전환, 답안 제출·보류, 강의안 이미지, 기록 보존·재접속, PC·모바일 화면으로 진행했습니다. **실제 사용자 GitHub Pages 계정에 게시하는 단계는 수행하지 않았습니다.**

자료의 재배포 권한을 확인한 뒤 GitHub Pages에 게시하세요. 원본 강의안/기출 캡처가 공개 저장소에 올라가면 외부인도 볼 수 있습니다.
